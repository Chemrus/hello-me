# Поводы (праздники) — сущность, а не страницы

Владелец 26.10.2026: «мы создаём новые страницы, а надо всё подводить к сущности… таких страниц можно миллион наделать» → «+».
**Правило:** новые страницы руками не делаем. Сущности: заведение (objects), событие (lf_event, афиша), список (lists — места без дат), повод (lf_occasion). Страницы — шаблоны, которые их собирают.

## Повод — `mu-plugins/lf-occasions.php`
- Таксономия `lf_occasion` у lf_event (и activities, festivals). Админка: «Поводы (праздники)». Поля повода (ACF на термине): ближайшая дата `lfo_start`/`lfo_end` (каждый год ставить новую), значок, для кого, коротко (календарь), вступление страницы, «вступление по городам» и «совет по городам» (строки `hanoi: …`), отсчёт до ЧЧ:ММ, список внизу (lists).
- Событию повода в админке (группа «Событие: для страницы повода»): короткое название, время, вход, адрес, карточка места (`lf_ev_place_id`, можно черновик — заработает при публикации), наш текст, анонс + подпись источника, метки (вечеринка, живая музыка, с детьми, бесплатно, 18+, улица/ТЦ).
- Страницы: `/vietnam/holidays/` — календарь (страница 19454, `[lf_occasions]`); `/vietnam/holidays/<ярлык>/` — та же страница с поводом (template_redirect подменяет запрос; `page_link` → адрес повода, иначе native-redirect темы уводит на календарь). Вкладки по городам, отбор по меткам, отсчёт, «В календарь», «Поделиться». Без событий — «ещё собираем».
- Кэш событий повода — transient `lfo_ev_<term>_<lfo_ver>`, `lfo_ver` +1 при сохранении события/повода.
- Ночная жизнь (hub-v3): календарь праздников берёт `lfo_upcoming()` — «Где отметить здесь: N →» (события города) или «в других городах»; ссылка «Все праздники».
- 15 поводов заведены (миграция `occasions-seed`): halloween, diwali, teachers-day, thanksgiving, christmas, new-year, tet (6.02.2027), valentines-day, lantern-festival, defender-day, womens-day, st-patricks-day, songkran, reunification-day, independence-day.
- Хэллоуин: 30 событий с поводом; старый адрес /vietnam/halloween-2026/ → 301 на /vietnam/holidays/halloween/, страница 19411 — черновик. Миграции halloween-2026 / hw-venues / occasions-seed читали данные из старого lf-halloween.php — повторно не запускать.
- Дальше (не сделано): кнопка повода в афише и виджете «Сейчас» в дни праздника; блок «Скоро: …» на странице города.

## «Постоянный праздник» — концепция (предложено 31.10.2026, ждёт решений владельца)
Владелец 31.10: праздники разных стран (Вьетнам, страны присутствия, страны гостей, может и другие), чтобы любое заведение могло сказать «сегодня день Камбоджи — в честь этого скидка»; все праздники — в **кабинет бизнеса** (отдельный от кабинета туриста, «там свои нюансы»).
Принцип: не новые страницы, а расширение сущностей. Повод = `lf_occasion`, акция = запись раздела «Новинки и скидки» (`lf-sales.php`, уже есть условия `lfs_cond`, «кому доступно» `lfs_who`) + шаблоны акций анкеты заведения (`lfvf_promos()`, 10 штук).
1. **Повод получает поля:** страна (флаг), тип (государственный / религиозный / национальный день / международный «день кофе»), **правило даты** (фиксированная, n-й день недели, лунный календарь — таблица дат на годы вперёд из официальных источников) вместо ручного `lfo_start` каждый год, **уместность** (праздник — можно акции / памятный день — без скидок: дни траура, памяти, посты), источник даты, идеи акций и готовый текст поздравления для заведения.
2. **Публичная страница повода — только когда есть что показать** (события или акции); остальные поводы видны лишь в кабинете бизнеса → не плодим пустых страниц.
3. **Акция к поводу:** у акции поле «повод» → показ на странице повода («Где отмечают со скидкой»), на карточке заведения (бейдж «🇰🇭 сегодня: … −15%»), в «Сейчас в городе» в день праздника, в кабинете туриста («сегодня ваш праздник» по стране из профиля).
4. **Кабинет бизнеса (отдельно от туристского):** мои заведения (подтверждённый владелец — `lf_owner_verified`, вход через /vietnam/boost/), календарь поводов на 60 дней с подсказкой «подходит вашей кухне», мастер «акция к поводу» в 3 шага (повод → шаблон → даты и условия → предпросмотр) → модерация в админке, готовые тексты и баннер, статистика показов и «Показать купон».
5. Этапы: данные поводов (CSV на проверку владельцу) → акция с поводом и показы → кабинет бизнеса MVP → «ваш праздник» у туриста.
Вопросы владельцу: какие страны во 2-м круге; где живёт кабинет бизнеса (letfind.me или LetFind.fun); можно ли скидку «только гражданам страны» или только «в честь праздника для всех»; бесплатно / сколько акций бесплатно.

## Анкета заведения к празднику (04.11.2026)
- Владелец: «как анкета по блюдам, только для праздников, разные страницы — разные QR; первое — Дивали; ресторан выбирает себя из текущих или вносит данные; скидка, предложения, вопросы».
- `mu-plugins/lf-occasion-form.php`: адрес `/vietnam/holidays/<повод>/for-venues/` для любого повода, кроме памятных. Язык по стране повода (RU/BY/KZ… — русский, иначе английский), переключатель `?lang=en|ru`. Английские названия поводов — карта в `lfof_name()` или мета повода `lfo_name_en`.
- Поля: город, заведение (подсказка из каталога → привязка к карточке, «это не мы» → адрес или ссылка на Google Maps); скидка 0/5/10/15/20/25/другая и на что; дополнительно (праздничный сет с ценой, сладости, напиток, буфет, музыка, оформление, дети, вечеринка, доставка); описание; даты (по умолчанию — даты повода), время; для кого; бронь; меню (полностью вег., вег. блюда, джайнская, халяль, веган, детское, алкоголь, доставка); ссылка на меню; вопросы; контакт.
- Ответы: админка «Анкеты к праздникам» + письмо админу. В ответе кнопка «Создать акцию (черновик)» → запись sales с поводом, местом, скидкой, датами, условиями (если ресторана нет в каталоге — сначала карточка, затем её номер). «Ссылки и QR» — адреса и QR ближайших праздников (скачать PNG).
- На странице праздника — плашка «Ресторанам, кафе и барам → Анкета заведения».
- QR Дивали для флаера: `data/qr/qr-diwali-letfind.png` → https://letfind.me/vietnam/holidays/diwali/for-venues/

## Дивали: страница праздника и примеры для ресторанов (05.11.2026)
- Владелец: «буду им отсылать примеры — как на карточке была бы скидка 10% в честь Дивали 8 ноября; страница Дивали с фильтрами, подборкой ресторанов и предложений, описание праздника».
- Код `mu-plugins/lf-occasion-extras.php`:
  - блок «О празднике» под шапкой берётся из меты повода `lfo_about` (HTML; Дивали — migrate occ-diwali-about);
  - пример на карточке: `?lfdemo=<слаг повода>` даёт плашку «Пример для заведения» со ссылкой на анкету, строку в «🏷️ Акции» и купон-чек темы (промокод = слаг + 10, например DIWALI10). Купон подставляется в `themes/letfind/sections/coupon-section.php` через `lfocx_demo_coupon()`;
  - `?lfdemo_v=<id>` на странице праздника ставит заведение первым с пометкой «−10% · пример»;
  - адреса примеров закрыты от поиска: X-Robots-Tag и `aioseo_robots_meta` (wp_robots перебивает AIOSEO), страницы не кэшируются. Без параметра ничего не видно.
- «Где отметить» (`lf-occasion-form.php`): все рестораны кухни по городам, сначала заведения с акцией, первые 6, затем «Показать все N». Фильтры: город, «с акцией», вегетарианские, халяль, допоздна, завтраки, с детьми, для пар (признаки из `lffd_flags`, см. food-filters.md).
- Список ссылок для рассылки: `data/diwali-demo-links.md` (17 Фукуок, 8 Дананг).
- Когда ресторан согласится: анкета → «Создать акцию (черновик)» → опубликовать sales. Тогда акция появится на карточке, на странице праздника и в /sales/ уже по-настоящему. Купон на карточке — ACF «coupon-group», как у Deer Cafe.
