# Задание 31 — закрыть чужие профили до открытия кабинета (19.10.2026)

Код: ветка `claude/sections` в `Chemrus/letfind-wp`, коммит **1050f95**, новый файл `mu-plugins/lf-private-profiles.php`. Выкладывать **до задания 27** (открытие кабинета всем).

## Зачем

Агент нашёл: по `/account/?user=<номер>` любой видит имя владельца профиля (публичный профиль WP-Recall). После входа через Google там будет настоящее имя, а номера легко перебрать. То же по `/?author=<номер>`: WordPress показывает страницу автора и для людей без единой записи (`/?author=1` → «Rus Che»). Владелец: закрыть.

## Что делает модуль

1. Чужой профиль WP-Recall (`/account/?user=N`, `/user/?user=N`, где N — не вы) → 302 на `/account/`.
2. Страница автора (`/?author=N`, `/author/<slug>/`) у пользователя без опубликованных записей → 404.
3. Авторы и эксперты, у которых есть опубликованные материалы, остаются публичными. Администраторы видят всё.

## Шаги

1. Выложить файл, `php -l`.
2. Проверить без входа (окно «инкогнито»):
   - `/account/?user=<номер тестировщика А>` → 302 на `/account/`, имени А нет;
   - `/?author=<номер тестировщика А>` → 404;
   - `/?author=1` и страница любого автора статей → открываются как раньше;
   - `/account/` сам по себе → как раньше.
3. Под тестировщиком Б: `/account/?user=<номер А>` → свой кабинет, не профиль А. Свой профиль `/account/?user=<номер Б>` открывается.
4. Под администратором: `/account/?user=<номер А>` открывается.
5. Если WP-Recall отдаёт профиль по другому адресу (страница кабинета не `account` или `user`) — прислать адрес, поправлю.
6. Ошибок PHP в логе нет.

## Откат

Удалить файл.
